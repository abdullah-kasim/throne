# Read before publish

`publish.sh` scrubs and greps a staged snapshot for a fixed pattern list. A
pattern list only catches names someone already banned. This skill adds the
part a pattern list cannot do: reading the shipped prose itself, in full, for
content that is general only in shape.

## Who may run the real publish

Only the Lord orders a real `./publish.sh`. A campaign agent (Regent, Alpha,
or Shadow) running this skill on its own initiative stops after step (d) —
findings fixed, dry run clean — and reports that state to its supervisor
instead of executing step (e). It never runs the real publish itself and
never asks the Lord to run it; it states the clean result and waits to be
told, or lets the Lord invoke this skill himself for step (e).

## Procedure

### (a) Stage, scrub, verify

Run `./publish.sh --dry-run` from the live throne root (absolute path or
`git -C`, never `cd`). It stages a snapshot, scrubs it, and verifies it
against the known pattern list, printing the staged path
(`dry run OK — N files staged at $STAGE`). A verify failure ends the run
here, naming the offending file and pattern — fix that at the private source
before continuing.

### (b) Read the staged snapshot

Rank the staged AGENTS.md, `agent_docs/*.md`, `.claude/skills/*/SKILL.md`,
README, and docs files with:

```
throne rank "Does this file name a real person, an employer, a colleague, an
internal hostname, an internal project, a ticket or pull request number, a
customer, a machine path, or a local username?" --top all --json <staged files>
```

The ranking orders reading, it never excuses skipping a file: read every file
above the ranker's threshold in full, skim the rest. Record every finding as
`file:line`, the phrase, and a general replacement that keeps the same shape
(what the passage teaches) while removing what leaks (the specific domain).

### (c) Fix at the private source

Edit the private source files, never the staged snapshot — the snapshot is
regenerated by (a) on the next run. One commit per file group. Re-run (a)
and repeat the read in (b) until verify passes and the read finds nothing
further.

### (d) Record new identifier classes

If the read surfaced a category of leak the pattern list did not already
cover, add it to `~/.config/throne/private-refs.txt` and to the scrub file's
`# verify:` list. Both files live outside this repo; this skill states the
requirement, it never writes to either file itself.

### (e) Real publish (Lord-invocation only)

`./publish.sh` for real, then grep the public clone once more for every
`# verify:` pattern and for the operator's name, handle, and employer. A
campaign agent never reaches this step on its own initiative — see "Who may
run the real publish" above.

## What this skill never does

- Never edits the staged snapshot instead of the private source.
- Never rewrites `publish-scrub.sed` — new patterns go in the external
  verify list (d), not into the checked-in scrub logic.
- Never runs a real publish except on the Lord's own invocation.
- Never blocks the Lord with a question; a campaign agent that hits a
  genuine decision reports it to its supervisor instead.
