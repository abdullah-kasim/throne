# Throne backend
Summary: Runs the long-lived server that hosts the message dispatch loop, the watchdogs and the web listener.
Code: src/throne-backend, src/delivery-callback, src/agent-settings, bin/throne-runtime, src/process-inspection/launch-count.ts
Search words: throne-backend, agent-settings-tick, pi settings, backend, worker, backend-vitals, child launches, memory, event-loop delay

## What it does

`throne-backend` runs on Bun, started by its service unit through `bin/throne-runtime`, the one launcher that names the runtime and runs the Bun pinned in `mise.toml`; procwatch still recognises its `ExecStart` behind the launcher and never touches it. It is the one long-lived process: it hosts keep-going, no-idling, the message queue's dispatch loop, the web listener, the delivery callback listener and the lost-message check as in-process workers. The callback listener serves only `POST /api/delivery-callback` on its own unix socket, `<throne home>/delivery-callback.sock`, mode 0600, removing a stale socket file first; the web listener's port does not serve it. A delivered callback moves an accepted message to delivered and schedules its receipt check, a refused one moves it to failed, and one for a message that is not accepted, or from another pane, changes nothing. The lost-message check runs once a minute (MQ-FAILURES). A message that cannot be delivered never kills it, and a callback socket that cannot be bound is logged and the backend runs on, agents then unable to call back while the lost-message check still covers their messages. `agent-settings-tick` checks every agent's colour and session name once and corrects what differs, in the backend or locally with `--local`. For a Claude agent whose mod's sign says `commands: true`, the `/color` or `/rename` correction goes to the mod as a command request, with no pane read or key: the request waits 2000 ms, not a message's wait; an ack means applied, a busy answer (the mod refuses a command while a turn runs) or a timeout while the mod still answers means skipped as busy, retried on the next check, so the command runs once after the turn, and anything else logs one fallback line and types the command once. An older mod, or none, gets the command typed as before. A pi agent's colour and name are read from its own pi session file (the newest `session_info` name and the newest `throne-agent-colour` entry) and corrected through its delivery extension as the same command request, when the extension's `GET /alive` says `commands: true`; delivered or accepted means applied, a timeout skips as busy, and a refusal fails. When the extension takes no commands, the command is typed into the pi pane only while it is idle with an empty composer. Codex agents are skipped. The correction right after a spawn skips its wait for the pane to take a command when the mod takes commands. Once a minute the backend writes one `[backend-vitals]` line to its journal: the child processes it launched in that minute (every `node:child_process` and `Bun.spawn` launch passes one counter), its resident memory in MB, and event-loop delay as mean, p99 and max in ms. A failed sample never stops the backend. Once it has sent READY=1 the app process sends `WATCHDOG=1` to systemd every 30 s, the only sender of that ping; keep-going does not feed the watchdog. The unit's `WatchdogSec=120` means an app process that dies or stops turning under a live `nest start --watch` parent gets the whole unit restarted within about two minutes.

## Sub-features

- BE-WORKERS: Dispatch, keep-going, no-idling, the delivery callback listener and the lost-message check run as workers of one process.
- BE-SURVIVE: An undeliverable message, or a callback socket that cannot be bound, does not stop the server.
- BE-BUN: The backend, the `throne` command and the hooks start through `bin/throne-runtime`; a missing pin or an uninstalled pinned Bun exits 1 naming the fix.
- BE-VITALS: One `[backend-vitals]` journal line a minute gives launches that minute, resident memory and event-loop delay.
- BE-WATCHDOG: Once it has sent READY=1 the backend app process sends `WATCHDOG=1` every 30 s and the unit's `WatchdogSec=120` restarts the unit after two minutes without one; keep-going never sends it.
- BE-SETTINGS: Claude and pi agents' colour and session name drift is corrected, through the Claude mod or the pi delivery extension with no pane read or key when it takes commands and typed into an idle, empty composer otherwise; `--dry-run` changes nothing. The session id comes from the agent's pane first and its spawn record second, and with none known nothing is typed.

Exits 0. `throne agent-settings-tick --local --dry-run` lists drift without changing it. `journalctl --user -u throne-backend | grep backend-vitals` shows one line a minute.

## Gotchas

Rebuilding `dist/` can restart the backend through its systemd unit. Bun cures the freeze Node had when launching a child from a big process; whether the backend still grows in memory is read from the `[backend-vitals]` lines, not assumed.
