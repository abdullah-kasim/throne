# Idle and nudge watchdogs
Summary: Nudges stalled agents, pages about idle families and untasked agents, wakes agents waiting on their own background run, and presses Enter on drafts stuck in an agent input box.
Code: src/keep-going, src/no-idling, src/scratch-pane, src/blocked-paging, src/supervisor-wait, src/supervisor-wait-monitor
Search words: keep-going, no-idling, find-untasked-agents, scratch-pane, blocked, idle, stuck draft, own-background-run, wake, supervisor-wait

## What it does

`keep-going` nudges the Regent or a named agent. Every check below learns an agent's state from its state file (see the agent state spec), never from its pane, so no timed check scrolls a pane to learn state. `no-idling` sweeps Alpha families that are fully idle: an agent whose file says `blocked` waits on the children it names, `waiting-on-own-run` and `waiting-on-supervisor` are waits, `reapable` is a reapable candidate (reason `fail` is a failed one), and `working` is busy while harness tool work runs, else idle. An agent that only printed a marker line with no state recorded is treated as working and idle. After a dependency-cleared wake the sweep sets the agent back to `working`. Each `no-idling` pass also reads the input box of every live Alpha, Shadow and the Regent; the same non-empty text in a draft box on two passes at least 60 seconds apart gets the forced Enter (MSG-ENTER-ONLY), which takes no lock and never types, clears or retypes. The sighting is kept with its first-seen time, so a box still stuck on the next pass is pressed again, on every pass, with no cap and no back-off. Any text counts, a human's half-typed line included; Stager boxes are never touched. A box showing a dialog, one that cannot be read, changed text, or a pane the stranded-spawn recovery handled in the same pass is never pressed. Each press logs one line with the agent and the first 80 characters; a refused press is logged and nobody is paged. Without `--notify` the pass presses nothing and prints the panes it would press. Sightings live in the sweep's memory, so a backend restart costs one extra minute. The blocked-agent pager wakes an agent whose state is `waiting-on-own-run`, the Regent and Stagers included. When an agent's turn ends (herdr reports the pane ready for input), the pager reads the tool processes under its pane at that moment and remembers them, so a run that ends before the next pass is still reported as ended. On every pass, before the stuck and still-working checks, it reads the tool processes under the agent's pane (pid, start time, command) and compares them with the ones remembered for that wait in `<data dir>/<agent>/own-run-wake.json`; a pane herdr reports working is not read at all. When a remembered process is gone (same pid and start time no longer present) it sends one message within a minute. No agent gets more than one own-run wake in five minutes for the same wait: an end seen sooner is kept and reported in the first wake after the five minutes pass. When the wait was declared at least 15 minutes ago and no wake went in the last 15 minutes it sends the same message again, with no cap. The message names each ended command and each still-running command with how long it has run, commands cut to 80 characters. When something ended, the line after it says: if the run you were waiting for is listed as ended, your wait is over: read its result, continue and end the reply without the marker, even if something is still running, and stop or ignore anything you are not waiting on. The message closes by telling the agent to read the result and continue, or, if still waiting, to check what holds the run up, run `throne my-state waiting-on-own-run "<what>"` and publish the marker again, and to fix the cause of a stuck run rather than restart it. A wake goes only to an idle pane by herdr's own status, never while the agent works, and never once the state is no longer `waiting-on-own-run`. A wake the queue could not type (recipient not addressable, or the not-sent retries ran out) is retried on the next pass with its ended commands kept; a wake still queued holds back the next one. An idle Alpha whose state has been `blocked` with no children for long enough, declared by itself rather than the Regent, gets one page to the Regent per declaration. The supervisor-wait monitor counts a Shadow as waiting on its supervisor when its state is `waiting-on-supervisor`, or `blocked` naming the supervisor, and it has sent the supervisor a message; once the slice is accepted it counts the Shadow's claim as made when its state is `reapable`. Reads asked for by hand (`agent-logs`, message delivery, model switch) still read any agent's pane, a Stager included. `find-untasked-agents` flags spawned agents nobody tasked; an agent with any state other than `working` is not untasked. `scratch-pane` registers an unnamed pane an agent opened on purpose so the unnamed-agent sweep stays quiet until its time ends.

## Sub-features

- WD-NUDGE: keep-going nudges by name.
- WD-BLOCKED: A `blocked` state naming children is resolved against them.
- WD-STATE-ONLY: no-idling, the blocked-agent pager and the supervisor-wait monitor decide an agent's state from its state file alone; `working` stops every page and wake.
- WD-SUPERVISOR-WAIT: A Shadow declaring `waiting-on-supervisor` that messaged its supervisor is paged to that supervisor when the wait stalls.
- WD-OWN-RUN-WAKE: An agent waiting on its own background run is woken when a process it waited on ends and every 15 minutes while it still waits, never more than once in five minutes.
- WD-QUIET-COORDINATORS: Periodic checks never read any agent pane's history to learn its state; a read by hand still does.
- WD-UNTASKED: A spawned but never-tasked agent is flagged.
- WD-STUCK-DRAFT: A draft unchanged for a minute in an Alpha, Shadow or Regent box gets the forced Enter on every pass until it changes.
- WD-SCRATCH: A registered scratch pane is ignored until its owner is gone or time passes.

It exits 0. On a live court, text left in a scratch pane's box is submitted by the running sweep within three minutes.

## Gotchas

Waiting on your own background work needs `throne my-state waiting-on-own-run "<what>"` (or, in Claude, the `BLOCKED_BY_own-background-run` marker that the turn-end hook records) or the Regent is paged. Start that work in the harness's own background mode, never with a shell `&`, and stop any server you started before ending a turn on the marker. While the live backend runs main, its pager can wake an evidence-tool scratch pane before the candidate's does; an F1 run counts only when the wake carries the candidate's wording. A wake the queue marks failed as already filled can sit unsent in the box until the stuck-draft press sends it. A message left in an agent's box is submitted after one to two minutes, so a line typed there by hand and left idle is sent too, and pressed again every pass if it does not go.
