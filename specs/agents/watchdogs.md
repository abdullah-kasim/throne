# Idle and nudge watchdogs
Summary: Nudges stalled agents, pages about idle families and untasked agents, wakes agents waiting on their own background run, and presses Enter on drafts stuck in an agent input box.
Code: src/keep-going, src/no-idling, src/scratch-pane, src/blocked-paging
Search words: keep-going, no-idling, find-untasked-agents, scratch-pane, blocked, idle, stuck draft, own-background-run, wake

## What it does

`keep-going` nudges the Regent or a named agent. `no-idling` sweeps Alpha families that are fully idle, honouring `{"blocked":true}` markers and the children they name. On a screen with no assistant-turn glyph, the agent's own text is what follows the last delivered message, whose end is either its sender-attributed line or its closing `</messageN>` line, so a marker quoted inside an incoming message is not taken as the agent's own. Each `no-idling` pass also reads the input box of every live Alpha, Shadow and the Regent; the same non-empty text in a draft box on two passes at least 60 seconds apart gets the forced Enter (MSG-ENTER-ONLY), which takes no lock and never types, clears or retypes. The sighting is kept with its first-seen time, so a box still stuck on the next pass is pressed again, on every pass, with no cap and no back-off. Any text counts, a human's half-typed line included; Stager boxes are never touched. A box showing a dialog, one that cannot be read, changed text, or a pane the stranded-spawn recovery handled in the same pass is never pressed. Each press logs one line with the agent and the first 80 characters; a refused press is logged and nobody is paged. Without `--notify` the pass presses nothing and prints the panes it would press. Sightings live in the sweep's memory, so a backend restart costs one extra minute. The blocked-agent pager wakes an agent whose latest message carries `{"blocked":true} BLOCKED_BY_own-background-run (...)` and names no child. The marker is read from the screen when the ledger has none, and the pager records it itself. When an agent's turn ends (herdr reports the pane ready for input), the pager reads the tool processes under its pane at that moment and remembers them, so a run that ends before the next pass is still reported as ended. On every pass, before the stuck and still-working checks, it reads the tool processes under the agent's pane (pid, start time, command) and compares them with the ones remembered for that marker in `<data dir>/<agent>/own-run-wake.json`; a pane herdr reports working is not read at all. When a remembered process is gone (same pid and start time no longer present) it sends one message within a minute; when the marker is at least 15 minutes old and no wake went in the last 15 minutes it sends the same message again, with no cap. The message names each ended command and each still-running command with how long it has run, commands cut to 80 characters. When something ended, the line after it says: if the run you were waiting for is listed as ended, your wait is over: read its result, continue and end the reply without the marker, even if something is still running, and stop or ignore anything you are not waiting on. The message closes: "If your run has finished, read its result and continue. If you are still waiting, first check what is holding the run up, then publish the marker again. If a run has gone on far longer than it should, it is stuck: find out what is holding it up and fix that cause; do not just start it again." A wake goes only to an idle pane by herdr's own status, never while the agent works, never for a marker naming a child, never after the marker is cleared, and never to the Regent; the Regent's one-time "nothing running" page is unchanged. A wake the queue could not type (recipient not addressable, or the not-sent retries ran out) is retried on the next pass with its ended commands kept; a wake still queued holds back the next one. `find-untasked-agents` flags spawned agents nobody tasked. `scratch-pane` registers an unnamed pane an agent opened on purpose so the unnamed-agent sweep stays quiet until its time ends.

## Sub-features

- WD-NUDGE: keep-going nudges by name.
- WD-BLOCKED: A blocked marker naming children is resolved against them.
- WD-OWN-RUN-WAKE: An agent waiting on its own background run is woken when a process it waited on ends and every 15 minutes while it still waits.
- WD-UNTASKED: A spawned but never-tasked agent is flagged.
- WD-STUCK-DRAFT: A draft unchanged for a minute in an Alpha, Shadow or Regent box gets the forced Enter on every pass until it changes.
- WD-SCRATCH: A registered scratch pane is ignored until its owner is gone or time passes.

## How to reach it and prove it works

```
bun test ./src/no-idling/blocked-marker-resolution.spec.ts ./src/no-idling/stuck-draft.spec.ts ./src/no-idling/stuck-draft-sweep.spec.ts ./src/blocked-paging/own-run-wake.spec.ts
```

It exits 0. `bun scripts/own-run-wake-evidence/run.ts all` proves the wake on real scratch panes running a real Claude harness and writes `~/tmp/own-run-wake-evidence/<timestamp>/log.json` with one PASS, FAIL or NOT VERIFIED per line W1–W12 and flow F1–F3. The tool counts a wake only once its queue item is delivered or failed (bound 15 minutes). F1 lets a real pager timer act with no pass by hand; F2 checks the harness stops a deadlocked run without restarting it; F3 only reads the backend log, queue records and two named agents' transcripts and never messages them. On a live court, text left in a scratch pane's box is submitted by the running sweep within three minutes.

## Gotchas

Waiting on your own background work needs the `BLOCKED_BY_own-background-run` marker or the Regent is paged. Start that work in the harness's own background mode, never with a shell `&`, and stop any server you started before ending a turn on the marker. While the live backend runs main, its pager can wake an evidence-tool scratch pane before the candidate's does; an F1 run counts only when the wake carries the candidate's wording. A wake the queue marks failed as already filled can sit unsent in the box until the stuck-draft press sends it. A message left in an agent's box is submitted after one to two minutes, so a line typed there by hand and left idle is sent too, and pressed again every pass if it does not go.
